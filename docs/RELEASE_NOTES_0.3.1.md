# EduCode 0.3.1 — Windows и Linux

Небольшое исправляющее обновление с единым номером версии, надёжным перезапуском Python-консоли и меньшей нагрузкой при большом потоке вывода.

## Список изменений для пользователей

- Исправлено отображение версии: главная страница, раздел «О программе», команда `EduCode --version`, журнал и установщик теперь получают номер из одного источника.
- Python-консоль полностью очищается перед каждым новым запуском. Вывод и история предыдущей программы больше не накапливаются.
- Исправлена неработающая клавиша `X` (`Ч` в русской раскладке).
- Обычные переменные Python (например, `name = ...`) снова отображаются белым, а не цветом именованных аргументов.
- Исправлен ложный счётчик `0 ссылок` у классов и функций во время Teacher Mode и при медленном запуске Pyright.
- Teacher Mode больше не отключает учеников при накоплении кадров демонстрации на медленном соединении.
- Windows-установщик автоматически находит предыдущую установку и предлагает «Обновить» без ручного удаления старой версии.
- В Windows-установщик и его окно добавлена иконка EduCode.
- Настройки горячих клавиш больше не позволяют назначить одиночную печатную клавишу и тем самым заблокировать ввод текста.
- Старые ошибочные привязки одиночных клавиш автоматически удаляются при запуске.
- Уменьшены кратковременные зависания интерфейса при очень большом выводе Python-программы.
- Снижено постоянное потребление памяти буферами консоли и терминала.
- Имя Windows-установщика и версия в списке установленных программ синхронизированы с версией проекта.

## Технические решения

### Единая версия

Единственный источник версии — строка `project(EduCode VERSION ...)` в корневом `CMakeLists.txt`. Во время конфигурации CMake создаёт `Version.h`. Приложение устанавливает из него `QCoreApplication::applicationVersion`, а QML читает `backend.applicationVersion`. Установщик использует тот же заголовок, а скрипт упаковки читает версию из корневого `CMakeLists.txt` для имени файла.

При следующем обновлении достаточно изменить только `project(EduCode VERSION 0.3.1 ...)`.

### Очистка Python-консоли

ANSI-последовательность очистки стирала видимую область, но не scrollback xterm.js. Поэтому старые строки продолжали жить в памяти и накапливались после каждого запуска. Перед стартом процесса backend теперь:

1. очищает внутренний буфер и флаг ошибки;
2. отправляет отдельный сигнал `consoleReset`;
3. xterm.js отменяет ещё не показанную очередь, очищает ввод и вызывает `term.reset()`;
4. только после этого запускается новый Python-процесс.

### Клавиша X / Ч

В пользовательском `config.json` была привязка:

```json
"editor.action.moveCarretLeftAction": "x"
```

Monaco регистрировал её как команду и перехватывал физическую клавишу `X`, поэтому раскладка не имела значения. Проверка конфигурации теперь разрешает глобальные и редакторские горячие клавиши только с `Ctrl`, `Alt`, `Meta` либо на функциональных клавишах `F1`–`F35`. Пустое значение по-прежнему отключает комбинацию. При чтении старой конфигурации небезопасные привязки удаляются, а основные команды получают стандартные значения.

### Оптимизация

- Убран `stateChanged` на каждый блок вывода процесса. Раньше при активной программе весь QML-интерфейс мог пересчитываться примерно каждые 33 мс; теперь обновление состояния происходит только при первом обнаружении ошибки и при изменении состояния процесса.
- Нативные буферы консоли и терминала уменьшены со 100 000 до 32 768 символов. Для контекста Лиры всё равно использовались только последние 30 000 символов, поэтому полезная информация не потеряна.
- Полный сброс xterm.js между запусками не даёт DOM/терминальному буферу расти от запуска к запуску.
- Сохранена пакетная передача вывода через 33 мс и `requestAnimationFrame`, чтобы не создавать обновление интерфейса на каждую строку.
- Не отключались WebEngine, Monaco, Pyright или фоновые индексы: это сломало бы основные возможности IDE. На компьютерах начала 2000-х WebEngine физически не запустится, но изменения уменьшают лаги и накопление памяти на слабых поддерживаемых Windows-системах.

### Цвет обычных переменных

Дополнительная подсветка PyCharm ошибочно считала любую конструкцию `имя =` именованным аргументом, если позже в строке встречалась открывающая скобка. Поэтому `name = input(...)` становилось оранжевым. Теперь именованный аргумент распознаётся только после `(` или `,`, например `open(file=name, mode="r")`; обычный идентификатор остаётся белым.

### Ссылки классов и функций в Teacher Mode

В журнале `ide-20261018-091501-637-0d11e0ee.log` обнаружены ошибки Monaco `Model not found` и неоднократное переполнение очереди кадров Teacher Mode свыше 4 МиБ. У счётчика была дополнительная ошибка состояния: запрос ссылок, сделанный до готовности Pyright или завершившийся по тайм-ауту, превращался в настоящее значение `0` и больше не пересчитывался.

Теперь CodeLens:

- принудительно обновляется после сигнала готовности Pyright;
- отличает временно отсутствующий ответ от настоящего пустого списка ссылок;
- повторяет временно неудачный запрос;
- отбрасывает запоздавший ответ, если модель файла уже закрыта, вместо ошибки `Model not found`.

Передача экрана Teacher Mode ограничена двумя кадрами в секунду. При сетевой очереди свыше 512 КиБ промежуточный кадр пропускается: код, правки и ping остаются отзывчивыми, а соединение не разрывается из-за устаревших кадров.

### Обновление через Windows-установщик

Установщик читает `InstallLocation` и `DisplayVersion` из записи удаления EduCode. Если приложение уже установлено, он показывает режим «Обновить», использует существующую папку и сохраняет выбор ярлыков.

Во время обновления старая папка атомарно переименовывается во временную резервную копию. Новая версия распаковывается на её место. Если распаковка или проверка файлов завершается ошибкой, установщик удаляет неполную новую папку и возвращает прежнюю. После успешного обновления резервная копия удаляется автоматически. Проекты и настройки находятся вне папки программы и не затрагиваются.

Если EduCode запущен и Windows не позволяет переименовать папку, установщик просит закрыть программу и повторить действие. Удалять старую версию вручную не требуется.

## Проверки перед выпуском Windows

- Собрать Release: `powershell -File tools/build.ps1 -Configuration Release`.
- Запустить `ctest --test-dir out/build/educode-qt5-release --output-on-failure`.
- Проверить `EduCode.exe --version` — ожидается `EduCode 0.3.1`.
- На главной и в «Настройки → О программе» должна быть версия `0.3.1`.
- Назначить `x` основной или редакторской горячей клавишей: настройка должна быть отклонена, ввод `x` и `ч` должен работать.
- Дождаться CodeLens у функции с использованием, включить Teacher Mode и убедиться, что настоящее количество ссылок не превращается в `0`.
- Запустить две разные Python-программы подряд: перед вторым запуском в консоли не должно остаться строк первой.
- Запустить программу со 100 000 строк вывода и проверить отзывчивость окна и завершение процесса.
- Собрать установщик: `powershell -File tools/build-installer.ps1`; ожидаемое имя — `EduCodeSetup-0.3.1-win64.exe`.
- Установить 0.3.0, запустить установщик 0.3.1 и проверить окно «Обновить». После обновления проекты, настройки и выбранные ярлыки должны сохраниться.

## Проверка Linux

Версия 0.3.1 перенесена и собрана на Ubuntu 24.04. Все общие исправления версии, консоли, горячих клавиш, подсветки, CodeLens и Teacher Mode используются Linux-сборкой без отдельной копии кода.

Linux-пакетирование также переведено на единый источник версии: `tools/build-deb.sh` читает номер из корневого `CMakeLists.txt`, записывает его в метаданные Debian и формирует имя `educode_0.3.1_amd64.deb`. Поэтому пакетный менеджер распознаёт новый файл как обновление установленной версии.

Проверено на Ubuntu:

- Release-сборка через `bash tools/build-linux.sh`;
- CoreTests и TeacherTests;
- команда `EduCode --version`;
- графический Linux smoke-тест: открытие файлов, интерактивный Python, Pyright, PTY-терминал, локальный API, снимок окна и корректное завершение;
- полный UI smoke-тест: ввод и редактирование, белый цвет обычных переменных, настоящее число ссылок после готовности Pyright, очистка консоли и большой поток вывода;
- содержимое и версия Debian-пакета;
- обновление установленной версии через пакетный менеджер.

Не следует переносить Windows-специфичный код `CREATE_NEW_CONSOLE`; он не связан с этими исправлениями и отделён директивой `Q_OS_WIN`.
